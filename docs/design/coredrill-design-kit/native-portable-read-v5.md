# Native portable archive input — IPC version 5

Date: 2026-10-21. Authority: ADR-0004, D-020/D-024/D-050/D-051, INT-006.
Status: implementation and focused proof in progress; normal restore remains open.

## Ownership and compatibility

The existing allowlisted archive command gains complete-ZIP input, not immediate restore. The frontend and Rust move from IPC 4 to 5 together; older versions fail closed. Existing save, attachment, backup and database-only recovery operations retain their semantics. SQLite, portable manifest/container and legacy recovery formats do not change. No filesystem/dialog JavaScript permission, dependency or command is added.

Rust owns a ZIP-filtered file picker and a private read-only selected file handle. TypeScript owns full ZIP/manifest/inventory/checksum inspection, temporary candidate SQLite inspection, conflict policy, explicit confirmation and atomic restore coordination. Selection never invokes legacy restore, commits a vault, updates export history or grants a restore capability.

## Serialized operations

- `portable_read_begin`: live session plus a fresh 32-byte random lowercase-hex `selectionId` generated by the adapter. This identity is ephemeral correlation, not a content checksum. Cancellation returns `portable_read_cancelled` with the same identity. A selected regular file must have a ZIP local-header prefix and length from 22 bytes through the existing 544 MiB ceiling. Rust streams a bounded initial hash, rewinds the same handle and returns only `portable_read_ready`, selection identity, exact length and SHA-256. The prefix is an early wrong-file check, not ZIP validity proof.
- `portable_read_chunk`: same session/selection and exact next offset. Rust returns at most 1 MiB, the matching offset and a boolean `complete`. Chunks are nonempty and ordered. Rust independently hashes the transferred stream; the final chunk is withheld unless its digest matches the initial read and exact EOF is observed. Changed, grown or truncated selected content fails without target mutation and drops the handle.
- `portable_read_release`: idempotent cleanup of that session/selection. An absent handle is a no-op acknowledgement, not evidence that this caller acquired or read anything. A different active selection in the same session cannot be released. Another session cannot read or retire the owning session's handle.

All new data shapes and the response envelope reject unknown fields. No source/destination path or filename is accepted in shipped IPC or returned. Selected paths originate only from Rust's OS picker; existing absolute/canonical/regular-file and direct-symlink checks apply. This does not claim a complete filesystem TOCTOU audit or close SEC-003.

## Lifetime and resource bounds

At most one live input handle or save stage exists across service sessions. Input retains a file handle and streaming hasher, not another whole-archive Rust buffer or a plaintext staging file. The initial hash uses a bounded buffer; individual chunk allocation is fallible and bounded. Closed/deleted/replaced sessions, WebView retirement, failure, final chunk or explicit release drop the handle. Idle handles expire after 15 minutes; validation or the next begin retires expired stages across sessions. Active SQLite transactions reject archive operations.

The TypeScript adapter serializes selection, transfer, release and close on its existing queue. It checks version/request/selection identity, length bounds, exact chunk offsets/lengths and completion, copies into owned bytes, and independently hashes the complete result before returning `selected`. It always attempts release of the original identity, including malformed/lost begin acknowledgements and cancellation. Cleanup failure prevents a successful result; an earlier failure remains primary and bounded expiry/session teardown provide fallback cleanup. There is no automatic retry, generic file-read fallback or browser file input in native mode. A new explicit attempt uses a fresh identity.

The 544 MiB ceiling is an enforced limit, not a demonstrated reference-device memory/performance claim. Shared inspection still uses reviewed in-memory owned copies. Maximum-vault profiling and REL gates remain open.

## Proof and normal restore boundary

Rust tests cover actual selected files, multi-chunk ordering, unchanged SQLite/source bytes, cancellation, wrong/foreign/replayed/expired identity, transaction rejection, mutual exclusion with save, close/retirement, malformed/oversized/changed/truncated/grown files, direct symlinks where supported, unknown request fields and old IPC versions. TypeScript tests cover strict response parsing, byte ownership, full hash mismatch, missing/short/oversized/foreign/misordered chunks, false completion, lost acknowledgement, explicit cleanup, serial lifetime and no restore operation.

The excluded diagnostic probe may receive a synthetic selected input path through host process argv only, never WebView JSON. Actual TypeScript-to-Rust proof selects the existing schema-160 synthetic full archive, runs shared inspection/preview, retires the preview and compares exact unchanged target bytes. A host-selected fixture is not installed OS-picker usability proof.

Normal root/session ownership, Settings and clean/onboarding entry points, browser input, explicit preview/confirmation/commit, navigation/reflow/failure and clean browser/native exact-content recovery remain required. This input prerequisite cannot close INT-006.
