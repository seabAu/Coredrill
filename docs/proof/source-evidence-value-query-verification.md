## Scope and boundary

`GetJobSourceEvidenceValueQuery` selects one normalized/raw value from one job field candidate or accepted requirement in an owned retained snapshot. Inputs and operation context are validated before storage. Default reads are 32,768 bytes, with explicit 4–65,536-byte bounds. Output is copied/frozen literal serialized JSON or text, never parsed objects, markup rendering instructions or trusted evidence. A field's absent raw SQL NULL is distinct from four bytes of JSON `null` or two bytes of serialized empty string. Requirement values and normalized field values cannot be absent/zero-length.

The shared adapter chooses SQL identifiers only from fixed evidence-kind/value-part maps and binds IDs, ceilings, offsets and lengths. One transaction queries only the selected BLOB substring and its total length, guarded by job ownership, snapshot/provenance/record creation ceilings and explicit archive scope. It does not retrieve whole records, write, fetch, confirm, supersede or change privileges. Field/requirement UUID identity is kind-qualified; equal UUIDs in the separate tables remain distinguishable.

Continuation binds job/snapshot/kind/record/part/archive/as-of scope, provenance ID, current row version and total serialized byte length. Missing records fail as unavailable scope; changed provenance/version/length and mid-scalar offsets fail with conflict. A current confirmation/category/supersession update deliberately invalidates an in-progress read even when source bytes remain unchanged; a fresh read is explicit recovery. Row-version continuity is not a newly computed checksum, protection against out-of-band same-version database tampering, or historical review-state reconstruction. Existing legitimate field-value writers update annotations with row-version advancement; accepted requirement source text/provenance are trigger-protected. No migration, dependency, permission or Accepted decision changes.

An internal `decodeLiteralUtf8Chunk` now serves both this second consumer and the existing retained snapshot content API. Fatal scalar-safe decoding defers only incomplete trailing UTF-8 scalars and preserves BOM/NUL/Unicode exactly; measured consumed bytes determine continuation, avoiding replacement, loss or duplicate bytes. The preexisting source-content contract and null/empty-body semantics remain intact.
