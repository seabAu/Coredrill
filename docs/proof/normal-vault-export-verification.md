Status: `INT-006` preparation prerequisite passes full local, separate extension and final documentation policy verification; exact committed hosted proof remains. This is not normal Settings, saved-copy verification or restore UI completion. No new dependency, schema, archive version, protocol, permission or Accepted decision.

## Required behavior

The complete archive must bind the viewed vault and application-owned archive identity/time, include the existing canonical database, all paired JSON/CSV datasets and every recorded attachment, and disclose encryption mode `none`. Missing/corrupt data must not produce a successful partial archive. Preparation cannot save a file, advance a backup/export reminder or imply that a recoverable copy exists outside the vault.

The read-only application query requires explicit unencrypted consent before opening either runtime store. It freezes copied intent, validates correlated archive/vault/time and safe filename, bounds/copies the byte result, checks SHA-256, validates the manifest and paired data inventory, strips extras and returns `prepared_not_saved`. Errors are redacted; no automatic retry or alternate runtime is available. Storage owns completeness and ZIP assembly; mock application acknowledgements are not evidence of real ZIP contents.

## Consistent source and exact-restore finding

The first coordinator verifies portable SQLite snapshots before/after the data, ledger and attachment reads. Initial actual-file tests pass ordinary mutation rejection, but `portable-vault-archive-aba-before.log` reproduces a stronger failure: an intervening vault-name projection is paired with exact restored original SQLite bytes. Both outer hashes agree. The original guard is therefore insufficient and is not accepted as complete proof.

The repair adds an optional in-process `DatabaseReadSnapshot` capability to the existing coordinator. Browser and native retain their existing operation queues, query/export protocols and SQL trust boundaries. The lease exposes only query/export, blocks queued operations until its callback settles and rejects capabilities used after success or failure. It is not a new native command, SQL transaction, external-process lock or generic filesystem permission. Callers must use only the supplied scoped methods during the lease, not queue nested operations on its parent database.

The archive coordinator fails closed when that capability is unavailable. It captures database bytes, complete validated data projections and ledger under one lease; attachment bytes are read afterward and checked against the captured content-addressed manifests. A final independently verified database snapshot conservatively rejects subsequent committed drift. Ordinary human-readable export retains its original transaction boundary and compatibility; the internal projection reader is reused without a nested transaction. This protects the owned runtime coordinator, not a device compromised by an external file writer.

Native storage permits multiple connections to one database. The coordinator therefore also reads the already-allowlisted SQLite `PRAGMA data_version` on its same connection before and after capture and after attachment assembly; external commits reject without returning an archive. No new pragma or native operation is authorized. A two-real-connection test changes the vault after the first snapshot, retains the intervening projection, then restores the original logical value. The pre-epoch probe already rejects this particular case through its outer hash check; the strengthened test additionally proves `data_version` rejects inside capture before final archive/snapshot assembly. Do not describe that probe as a failed test.

[SQLite's official data-version contract](https://www.sqlite.org/pragma.html#pragma_data_version) requires comparing observations on the same connection and distinguishes other-connection commits from that connection's own writes. That is why the implementation combines the counter with the coordinator lease and verified byte snapshots instead of comparing counters across connections or treating the counter as a global stored revision.

`native-export-read-transaction-probe.log` separately confirms that the accepted native boundary rejects archive export during a transaction. The experiment was reverted, not used to weaken the guard. The lease remains an in-process queue capability with optimistic SQLite data-version validation, not a new SQL transaction or cross-process file lock. Its consistent-result guarantee covers ordinary commits on other SQLite connections; arbitrary out-of-band physical file replacement by a compromised device remains outside this boundary.
