## Scope and boundary

The typed query lists job `field_value` candidates and accepted `job_requirement` rows for one owned retained snapshot. It validates operation context, IDs, archive scope and default-25/maximum-50 page limits before storage. Cursors bind job, snapshot, archive scope, immutable local creation ceiling and exact creation/kind/ID anchor. Deterministic order is creation descending, kind ascending, ID ascending. Evidence identity includes kind so coincident UUIDs in separate tables remain distinct. An owned empty snapshot differs from unavailable scope; missing anchors fail with conflict.

The SQLite adapter binds all values, validates ownership and anchor in the read transaction, and requests at most limit-plus-one rows. JSON/text values are literal 256-codepoint previews with original UTF-8 byte lengths and explicit completeness. No parsed objects, markup execution, fetch, confirmation, write, dependency, permission or schema change is introduced. A separate full serialized-value accessor remains required before Source UI can claim complete values.

The application copies/freezes nested data and validates scope, provenance method/pointer/excerpt/confidence, complete JSON syntax, preview size/completeness, chronology, ordering and exact continuation. Current review annotations may legitimately be newer than the membership ceiling. Original confirmation IDs/times/hashes and supersession targets remain preserved; a superseding row must belong to the same job/field with its real snapshot reference. An unsuperseded candidate is not asserted to equal the main job's resolved value. Requirements retain immutable source category/text/provenance, current corrected category and stored confirmation boolean; no confirmation ID/time/hash is invented. Extraction confidence is not a hiring score or truth certificate.
