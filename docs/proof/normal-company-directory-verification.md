## Runtime and read-coordination scope

`stored-company-directory.ts` composes the validated application query with the shared SQLite repository. Application validation/copying precedes awaited selected-runtime opening. The main runtime applies the same migrations and uses its existing host-selected database without a new store or browser/native fallback. Errors remain application-owned and content-free. The port adds no network, enrichment, update or sending capability.

`stored-company-directory-reader.ts` retains one bounded current page and an immutable original vault/archive/limit owner, not the whole directory or a vault total. First and Next are explicit reads; Next replaces the page. Initial absence of data is not confirmed emptiness. Single flight prevents overlap; disposal revokes later publication, including synchronous disposal during busy-state publication. Results from a retired owner cannot enter a new vault's reader. Failure retains old facts as explicitly stale and never clears canonical data. Retry repeats only a retryable failed read; changed scope, invalid continuation or conflict requires a fresh first page. Live keyset pages are not an immutable historical snapshot, and a current page does not prove unqueried relationships or totals.
