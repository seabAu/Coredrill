# Saved-job requirement source review

Date: 2026-10-19. Scope: the requirement-creation gap within `Q3-005`; the full canonical journey remains open.

## Behavior and boundaries

The real saved-job Requirements route now derives deterministic version-1 proposals from the latest immutable retained plaintext snapshot. It uses the parser's reviewed heading vocabulary, preserves original one-based line coordinates across blank lines and CRLF/LF/CR separators, and retains exact line excerpts. Inputs exceeding the source, line-count, excerpt, or proposal budgets yield an explicit notice without losing access to the saved job or silently truncating its source. HTML, URLs, and instruction-shaped text remain inert; no source is fetched and no AI is called.

Pending identities combine the retained snapshot UUID with the deterministic parser identity. No provisional provenance ID is exposed as a durable fact. Acceptance accepts an identity and category, not caller-supplied requirement text: the runtime reloads the same-job snapshot and resolves the proposal again, then the existing application command allocates the real local requirement/provenance identities. One SQLite transaction rechecks the active job, exact retained line and coordinates, rejects an already-accepted snapshot/line, inserts heuristic provenance with the exact original excerpt and parser confidence, and records the user-confirmed requirement. Failed writes roll back the provenance too. Current category and immutable parser source category remain distinct.

Parsing and rejection do not write. As the accepted `MAT-002` design specifies, rejection hides only the current view's proposal; explanatory copy says it returns on reload. Accepted source/line identities are filtered from future projections, so accepted requirements survive reload without becoming pending again. Old confirmed requirements are never overwritten by reparsing or a later source snapshot. Snapshot and provenance data continue to use existing portable export/recovery datasets; schema remains 158.
